## 监控设置开关保存 bug 修复（4个 commit）

### 问题
运营设置 → 监控设置里的三个开关（定时测试所有通道、失败时自动禁用通道、成功时自动启用通道）勾选后保存报"你似乎并没有修改什么"，刷新后恢复未勾选。

### 根因分析（逐步排查）
1. **commit `cd7d926c`** — 子组件 `useEffect` 用空对象覆盖 state，缺失 key 导致 `compareObjects` 检测不到变化 → 修复：`{ ...inputs }` 展开
2. **commit `12c696ac`** — 父组件 `OperationSetting.getOptions` 同样用空对象，refresh 后丢失 key → 修复：同上
3. **commit `d496da24`** — 提取 DEFAULTS 常量避免 React 闭包捕获旧 state → 但仍未解决
4. **commit `2e508514`** — **真正根因：Semi UI `<Form values={inputs}>` 受控模式**。Switch onChange 更新 state → state 变化触发 re-render → Form 用新 values 同步所有字段 → 又触发 onChange → 值被覆盖回去。**修复：重写为 `initValues` + `formApi.setValues()` + `formApi.getValues()` 模式**

### 最终方案
- 去掉 `<Form values={inputs}>` 受控模式
- 用 `initValues={DEFAULTS}` 初始化
- `useEffect` 里用 `formApi.setValues(merged)` 同步服务器数据
- 提交时用 `formApi.getValues()` 直接读取 Form 当前值
- 用 `useRef` 存已保存的快照（不受闭包影响）
- 去掉所有 Switch 的 onChange（让 Form 自己管理状态）

### 教训
- **Semi UI Form 的 `values` prop 是完全受控模式**，会在每次渲染时同步所有字段值，容易和 onChange + setState 形成循环
- 对于设置页面这种"加载 → 编辑 → 提交"模式，用 `initValues` + `formApi` 更可靠
- 这个 bug 影响所有运营设置子组件，但只有 boolean 开关类型的字段会暴露问题（因为其他字段在 DB 中有值）

## 监控设置功能逻辑梳理
- **定时测试所有通道**: 按间隔测试，超时或报错自动禁用，恢复正常自动启用
- **失败时自动禁用通道**: 正常请求转发失败时，匹配状态码/错误码/关键词则禁用（需渠道开启 AutoBan）
- **成功时自动启用通道**: 仅对"被自动禁用"的通道生效，请求成功时恢复
- 核心代码: `service/channel.go` (ShouldDisableChannel/ShouldEnableChannel), `controller/channel-test.go` (testAllChannels/AutomaticallyTestChannels)

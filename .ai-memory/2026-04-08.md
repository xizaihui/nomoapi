## 完成的工作

### v0.2.5 — mimalloc v3 默认分配器

### v0.2.6 — 指纹优化：移除 DNT/Sec-GPC
- 用 `/tmp/wreq_probe/` 独立项目验证 wreq Chrome144 emulation 实际发送的 headers
- 发现 Accept-Encoding 和 Priority 已由 wreq 自动注入，不需要手动加
- 发现 DNT:1 和 Sec-GPC:1 是 Chrome 默认不发的，多账号全发 = 批次指纹信号
- 移除这两个头，Commit `18cde79`

### 上游同步分析 (v0.12.24)
- 上游大重构（-4824 行），引入 ractor actor 模式，删除 dashmap/rusqlite/prometheus 等
- 大部分改动和我们的 fork 冲突太大，不适合 merge

- 上游 `master` 分支

## 部署事故
- 部署 v0.2.6 时，SCP 过程中 exec 被 SIGTERM（超时），导致 clewdr 停了但新 binary 没上去
- 用户看到 HTTP 500 和服务 inactive
- 教训：部署流程应该先上传新文件（SCP），再 stop→mv→start（原子操作），不要在同一个 SSH 命令里做 stop + SCP
- 已修正流程：先 scp 到 clewdr.new → stop → mv → start

## 指纹审计结论
- 整体评分 B+/85分
- TLS 层（JA3/JA4/HTTP2 frames）由 wreq Emulation::Chrome144 处理，非常扎实
- HTTP headers 完整，Accept-Encoding/Priority 自动注入
- Sec-CH-UA 品牌字符串格式与 Chrome 真实值有细微差异（Not.A/Brand vs Not(A:Brand），但修改需要和 UA/Platform 保持一致，风险较高，暂不动
- Chrome 144 版本号在 2026 年可能已过时，但需等 wreq 库支持新版本

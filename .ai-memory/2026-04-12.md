## 改动概要

### 1. doubao adaptor — EstimateBilling 方法
**文件**：`relay/channel/task/doubao/adaptor.go`

新增 `EstimateBilling(c *gin.Context, info *relaycommon.RelayInfo) map[string]float64`：
- 检测请求中是否含参考视频（metadata 里 `video_url` / `reference_video` / `video` 类型，或 content 数组中 type=video/video_url）
- 含参考视频 → 返回 `{"reference_video": 0.6}`（0.6x 折扣）
- 不含 → 返回 nil（原价）
- 日志：`[doubao] reference video detected, applying 0.6x discount, model=xxx`

### 2. relay_task.go — OtherRatios 始终应用
**文件**：`relay/relay_task.go`（第 6 步）

**Bug 修复**：原代码在第 6 步用 `TaskPricePatches` 白名单跳过 OtherRatios 乘法，导致按次计费模型的折扣不生效。

修改前：
```go
if !common.StringsContains(constant.TaskPricePatches, modelName) {
    for _, ra := range info.PriceData.OtherRatios {
        info.PriceData.Quota = int(float64(info.PriceData.Quota) * ra)
    }
}
```

修改后：
```go
// 注：按次计费模式（TaskPricePatches）也需要应用折扣，
// TaskPricePatches 仅控制是否跳过任务完成后的 token 差额结算。
for _, ra := range info.PriceData.OtherRatios {
    if ra != 1.0 {
        info.PriceData.Quota = int(float64(info.PriceData.Quota) * ra)
    }
}
```

**原因**：`TaskPricePatches` 的本意是跳过任务完成后的 token 差额结算（按次计费模式），不应跳过预扣阶段的折扣乘法。

### 3. docker-compose.yml — 环境变量
加入 `TASK_PRICE_PATCH=T0101006`，将 Seedance 2.0 模型加入按次计费白名单。

## 计费设计

### 价格换算
- NewAPI 后台模型价格单位：$/1M token
- 1 美元 = 500,000 quota（NewAPI 固定惯例）
- 换算：¥/K token × 142.857 = $/1M token（按汇率 7）

### Seedance 2.0 价格
| 场景 | 火山价格 | 后台配置 ($/1M) | Quota/次 |
|------|---------|----------------|----------|
| T2V（纯文本）| ¥0.05/K | $7.142857 | 500 |
| I2V/V2V（含媒体）| ¥0.03/K | 自动 ×0.6 | 300 |

### OtherRatios 机制
- `EstimateBilling` 返回 `map[string]float64`，key 名任意，value 是乘数
- `relay_task.go` 第 6 步循环连乘所有 ratio 到 `info.PriceData.Quota`
- Sora 用 `seconds` + `size`；Seedance 用 `reference_video`

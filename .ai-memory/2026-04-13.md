## ClewdR: Sentinel 泄露修复

### 问题
OpenClaw 工具调用使用 sentinel 标记格式（`⟦CDR_TOOL_BEGIN:req_xx:nonce_yy⟧`），这些标记在 Claude 回复中被原样输出后泄露到 WhatsApp。原因是 clewdr 只识别自己的 sentinel（匹配 req_id/nonce），对上游（OpenClaw）的 sentinel 当作普通文本透传。

### 修复
在 `sentinel_parser.rs` 新增 `strip_sentinel_patterns()` 函数，按行过滤包含 `⟦CDR_TOOL_` 或 `CDR_TOOL_BEGIN/END` 的行。

在 `response.rs` 的 **6 处文本出口** 全部加了清洗：
1. 非流式 — `remaining_text`（有 tool_call 时）
2. 非流式 — 无 tool_call 时的完整文本
3. Claude 流式 — `remaining`（有 tool_call 时，ContentBlockStop）
4. Claude 流式 — buffer 直接 flush（无 tool_call 时）
5. OAI 流式 — `remaining`（有 tool_call 时）
6. OAI 流式 — buffer 直接 flush（无 tool_call 时）

新增 3 个测试用例验证 strip 函数。

### 注意
- clewdr 层修复是 belt-and-suspenders — 真正的 sentinel 泄露源头在 OpenClaw 消息路由层
- OpenClaw 应该在发送到 WhatsApp 前剥离自己的 sentinel，但目前没有完全做到
- 这不影响 API 层面的正确性（tool_use block 正常返回）

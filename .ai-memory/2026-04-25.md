## 🐛 重复 Poller Bug 修复（03:18 UTC）
- **现象**: 画图进度消息全部发两遍，且卡在 80% 不继续
- **根因**: 启动时 `LoadPersistedBots()` 和 `EnsureConfigBots()` 都调用 `manager.AddBot()`，导致同一个 bot 注册了两个 poller goroutine
- **影响**: 两个 poller 同时 long-poll → 同一条消息入队两次 → 两个 worker 各处理一次（进度×2）；两个 worker 竞争同一个画图 API 请求，其中一个可能超时（卡在 80%）
- **修复**: `connection.Manager.AddBot()` 增加去重检查 — 如果 bot 已有活跃 poller 则跳过，不再重复注册
- **教训**: 多个启动阶段都可能触发 bot 注册，连接管理器必须做幂等保护

## 参考图功能调试与优化（10:26-11:00 UTC）

### 修复记录

1. **multipart form 修复**: `/v1/images/edits` 需要 multipart form 上传，之前用 JSON + base64 导致 500 `convert_request_failed`。重写 `generateImageEdit()` 用 `mime/multipart` 构建请求体。

2. **413 Request Entity Too Large**: 图片 base64 编码后太大，上游 nginx 拒绝。新增 `resizeForVision()` 函数，发给视觉 AI 前先压缩到 1024px（nearest-neighbor 缩放 + JPEG 85%）。

3. **SSE 流式响应解析失败**: `analyzeImageWithAI` 收到 SSE 流式数据（`data: {...}`），不是 JSON。原因是 `visionChatRequest` 没有 `Stream` 字段，API 默认流式。加了 `Stream bool json:"stream"` 并设 `false`。

4. **gpt-5.4 不支持视觉**: 发图片 base64 给 AI，它说"请上传图片" — 根本看不到。改为不发图片，纯文字生成创意建议。

5. **动态欢迎语**: 收图后的固定回复改为 AI 生成（`generateImageAck`），每次不同，不描述图片内容（看不到），只给创意编辑建议。

6. **去 emoji**: 所有参考图流程的消息去掉了 emoji（"🔍 正在分析" → "正在分析"，"💡 如果描述没问题" → "如果描述没问题"）。

7. **进度条统一**: 参考图编辑的进度流程改成跟文生图一致 — SendText 每10秒一次进度条，80%后"正在渲染"提示，不用 SendStreamingText。

### 当前参考图完整流程
1. 用户发图 → `handleIncomingImage` 下载保存 → `generateImageAck` 调 AI 生成随机欢迎语+建议
2. 用户说"分析/写提示词" → `isAnalyzeRequest` 匹配 → `analyzeImageWithAI` 纯文字生成3-5个提示词建议 → 参考图保留（Store回sync.Map）
3. 用户发提示词 → `handleImageEditWithRef` → multipart form 调 `/v1/images/edits` → 进度条 → 发图

### 关键教训
- **gpt-5.4 不支持视觉** — 不要给它发图片 base64，会瞎编内容
- **`/v1/images/edits` 必须 multipart form** — 不能用 JSON body
- **上游 nginx 有 body size 限制** — 大图必须先压缩再发
- **API 默认可能是流式** — 非流式调用必须显式 `stream: false`

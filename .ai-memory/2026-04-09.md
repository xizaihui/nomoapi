## v0.2.7 — 入站 XML Tool Call 消毒器

### 背景
Claude 偶发在 assistant text 里输出 XML 格式的 `<tool_call>` 标签（而非原生 tool_use block）。
客户端将 XML 原样保存到对话历史 → 下一轮模型看到 few-shot 示例 → 继续写 XML → 恶性循环。
用户看到满屏 `<tool_call>` 原始标签。

### 解决方案
**commit `1926498`** — 在 clewdr 转发请求给 claude.ai 之前，扫描 assistant 消息 + system prompt，
将 XML tool_call 片段替换为 `[prior tool_use: NAME]` 占位符。

### 新增文件
- `src/middleware/claude/xml_sanitizer.rs` (372行，含 19 个单测)
- 5 种正则覆盖：完整闭合、未闭合、`<function_calls>`、`<invoke>`、孤立子标签
- 配置项: `sanitize_xml_tool_calls = true` (默认开启)

### 修改文件
- `request.rs` — 在 `sanitize_messages` 之后挂载 XML 消毒器
- `clewdr_config.rs` + `constants.rs` — 新增配置字段和默认值
- `mod.rs` — 注册 `xml_sanitizer` 模块

### 踩坑
- **Rust `regex` crate 不支持 look-ahead `(?=...)`** — 原始正则用了 lookahead 导致编译失败，改用非贪婪匹配解决

## XML 泄漏根因终极确认

### 三方防线现状
| 层 | 机制 | 状态 |
|---|---|---|
| 入站（请求历史）| `xml_sanitizer::sanitize_assistant_xml` + `sanitize_system` | ✅ 已部署，每轮触发 |
| 出站（非流式响应）| `tool_sim` 升级 + `sanitize_text` fallback | ✅ 已部署 |
| 出站（流式响应）| `transform_stream` 里的 `<tool_call` 检测 | ⚠️ 已有基础版，但只检测 `<tool_call` 前缀，不覆盖 `<function_calls>` 等变体 |

### 关键认知：XML 泄漏是所有 clewdr + OpenClaw 用户的通病
- Claude 模型偶发在 text 里写 XML 工具调用（模型行为，所有用户共有）
- OpenClaw 解析器遇到畸形 XML 解析失败时透传原始文本
- compaction 保留 XML → few-shot 自我强化 → 恶性循环
- clewdr 的入站 sanitizer 大幅降低频率，但无法 100% 消除当前轮回复里的流式 XML

### 自回复毒害教训 ⚠️
- **绝对禁止在回复文本中输出字面量 XML tool_call 标签**
- 已写入 AGENTS.md 禁止规则 + MEMORY.md 踩坑记录
- 原因：OpenClaw 解析器误解为工具调用 → 解析失败 → 对话中断 → compaction 污染

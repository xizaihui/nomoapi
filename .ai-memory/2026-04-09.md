# 2026-04-09

## ClewdR XML 消毒器全面加固 (v0.12.25)

### 背景
OpenClaw 通过 clewdr 代理接入 Claude 时，模型回复中如果包含 XML 工具调用标签（即使只是在讨论中提及），会导致：
1. clewdr 流式过滤器截断后续文本
2. OpenClaw 解析器误判为工具调用 → 会话中断
3. compaction 保留 → 污染后续所有对话

### 发现的 5 个漏洞 (commit 7cd6286)

1. **`types/claude_web/response.rs` 撇号 typo（致命）** — 匹配字符串末尾多了 `'`，过滤器从未触发过，claude.ai web 流完全裸奔
2. **同一文件只检测 tool_call** — 缺 function_calls 和 invoke 两个变体
3. **`claude2oai.rs` 同样只检测一种变体**
4. **`text_looks_polluted()` 大小写敏感** — Mixed_Case 变体绕过
5. **缺少未闭合 function_calls 正则** — 新增 `RE_FUNCTION_CALLS_UNCLOSED`

### 流式误杀修复 (commit 7dcec7d)

**问题**: 修完漏洞后，过滤器变得太激进——模型在 backtick 或 code fence 里讨论 XML 标签时也被截断

**方案**: 新增 `is_real_xml_tool_tag(buf)` 函数
- 找到标签位置 → 检查前面 backtick/fence 计数 → 奇数=代码上下文=不触发
- 应用到 3 个流式路径（claude_web、claude2oai、response non-tool filter）

### 教训
- clewdr 渠道讨论 XML 标签会触发自身的过滤器 — 当时连续中断 3 次后切回官方 key 完成修复
- 流式过滤器不能用简单的 `contains` 做检测，必须考虑代码上下文
- 增量编译 ICE (`evaluate_obligation`) 用 `cargo clean -p clewdr` 解决

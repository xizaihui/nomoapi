## 🚨 生产服 38.58.59.161 紧急救援

**症状**: api.opentoken.io HTTP 502，new-api 容器 exited (exitcode=128)

**根因链**:
1. Docker embedded DNS (127.0.0.11) 崩溃 → 容器名解析失败 (`lookup postgres: i/o timeout`, `lookup redis: i/o timeout`, `api.anthropic.com: server misbehaving`)
2. new-api 启动时连不上 postgres/redis → `panic: assignment to entry in nil map` at `InitChannelCache`
3. `restart: unless-stopped` 失效，containerd task 残留

**修复步骤**:
1. `systemctl restart docker` (重启 daemon 修复 DNS)
2. postgres/redis/es 自动拉起
3. new-api 仍然起不来，报 `task already exists`
4. `docker rm -f new-api` 清理残留 task
5. `docker compose up -d` 重建成功

**新踩坑教训**（已记入 MEMORY.md）:
- Docker daemon 重启只修 DNS，不会自动拉起 exited 的容器
- 遇到 `task already exists` 必须先 `docker rm -f <name>` 清 containerd 残留再重建
- 单 `docker compose up -d` 不够，需要先清理

## OpenToken: Semi Form Switch 保存失效修复

### 问题
运营设置页面（SettingsGeneral）中多个 `<Form.Switch>`（PlaygroundEnabled / DemoSiteEnabled / SelfUseModeEnabled / DefaultCollapseSidebar / DisplayTokenStatEnabled）点击切换后，保存时后端收到的值不变——UI 上看起来翻了，但 `inputs` state 里的字段始终是初始值。

### 根因
`<Form values={inputs}>` 是 Semi UI 的**完全受控模式**。在受控模式下，Form 内部每次渲染都会用 `values` prop 同步所有字段。而现有代码给每个字段都单独挂了 `onChange={handleFieldChange(fieldName)}`，但对于 Switch 这种 `valueKey: 'checked'` 的组件，withField HOC 的事件分发在受控模式 + `values` 同步的组合下存在竞争：Switch 切换后 Form 内部把值同步到 foundation，外层 setInputs 来不及 commit 就被下次 render 的 `values={inputs}`（旧值）覆盖，导致 state 永远不更新。

Input 组件没问题（valueKey=value + 正常的 onChange 链路），只有 Switch/Checkbox 这类 `valueKey: 'checked'` 的组件受影响。

### 修复
在 `<Form>` 上统一加 `onValueChange` 回调，把 Form 内部值全量同步回 `inputs` state，不再依赖每个字段自己的 `onChange`：

```jsx
<Form
  values={inputs}
  getFormApi={(formAPI) => (refForm.current = formAPI)}
  onValueChange={(values) => {
    setInputs((prev) => ({ ...prev, ...values }));
  }}
  style={{ marginBottom: 15 }}
>
```

验证：用户切换 Playground 开关 → 保存 → `onValueChange` 日志里 `PlaygroundEnabled: false` 正确传递，保存成功。

文件：`web/src/pages/Setting/Operation/SettingsGeneral.jsx`

### 教训 / 规律
- Semi `<Form values={...}>` 受控模式下，**不要**再依赖每个字段单独的 `onChange` 回到外部 state，统一用 `onValueChange` 在 Form 级别同步。
- 旧项目代码大量使用 `handleFieldChange(fieldName)` 模式，对 Input 类字段是偶然能工作的（受控回写时序刚好没冲突），但对 Switch/Checkbox 会静默失败。
- 后续类似设置页面（Operation 下其他 Settings*.jsx）如果有同样写法，都应改成 Form 级 `onValueChange`。
